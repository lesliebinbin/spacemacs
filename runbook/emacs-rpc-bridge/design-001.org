** Context and objective

Expose a small gateway into Emacs so an external Ruby, Python, Rust, or other
program can call Lisp functions and manipulate existing Emacs objects.
Use protobuf messages and gRPC-generated client/server interfaces. Emacs
owns buffers, windows, frames, and other Lisp objects; clients hold opaque
remote handles rather than copies of internal C structs.

The module API is a compact function table. =intern= and =funcall= provide
access to many Lisp functions without one RPC per editor operation.
=current-buffer= is a Lisp function called through that gateway, not an
entry in =emacs_env=. =make_function= registers a local C callback; it
cannot accept a function pointer from another process.

** Architecture and execution model

External client -> local gRPC endpoint -> bounded request queue -> Elisp
timer calls native drain function -> live emacs_env -> Lisp function.
Results travel back through a completion queue to the waiting RPC worker.

For the first milestone, use a Unix-domain socket in a private per-user
runtime directory. Keep the socket directory owner-only. Do not listen on
an externally reachable TCP address. This API grants editor-level authority
to clients that can connect; it is not a sandbox for untrusted code.

Network workers decode messages and wait for completions. They must never
call the Emacs API, dereference Lisp handles, or retain =emacs_env *= for
later use. The Elisp timer invokes a registered native function on Emacs's
main thread with a fresh valid environment. Start with polling; an event
wakeup mechanism can follow after correctness is established.

Bound both queue length and work drained per tick. Do not hold queue locks
while calling Lisp. A long-running Lisp call can still block Emacs: RPC
does not make arbitrary Lisp execution parallel or preemptible.

Backpressure decision (2026-09-08): when the request queue is full, server
handlers WAIT for a free slot (blocking backpressure) instead of failing
fast. A full queue means Emacs is behind; the client's own deadline is the
escape hatch, and backpressure naturally propagates up to channel/socket
buffers. This bounds in-flight memory by max concurrent handlers, not by
queue depth alone. =stop()= must broadcast/wake handlers blocked on a full
queue (and on completions) before joining them.

Runtime knobs (2026-09-08, decided; defaults set by the user):
- Queue depth =100 (defcustom =emacs-rpc-bridge-queue-depth=).
- Drain timer period =0.1 s/100 ms (defcustom =emacs-rpc-bridge-timer-period=).
  Interval is fixed at timer creation, so the defcustom needs a =:set= hook
  that cancels/recreates the timer while the bridge is running.
- Max work per drain tick =20 requests (defcustom
  =emacs-rpc-bridge-max-drain-per-tick=): bounds the longest single stall of
  the editor to one tick's slice; remaining requests wait for the next tick.
  Sustained throughput ceiling ~200 calls/s; the queue absorbs bursts above
  that and wait-backpressure pushes the excess to clients.
- Queue depth and the per-tick bound are fixed at =native-start= time (the
  C++ side sizes its queue/tick budget once); changing them mid-session
  takes effect after stop/start.

** TODO 2. Define the protocol contract

Use a separate versioned package, for example =emacs.rpc.v1=. First define
the exact wire contract and examples; then generate bindings.

Initial operations:
- =OpenSession=: negotiate protocol version and return a session identity.
- =Call=: function symbol name plus typed arguments, returning a typed value
  or structured Lisp error. Intern function names locally when dispatching.
- =ReleaseHandles=: release session-owned references explicitly.
- =CloseSession=: queue reference cleanup on the Emacs thread.

An explicit =Intern= RPC is optional: symbol names can be represented as
values, and =Call= already combines lookup and invocation.

Values should distinguish nil, true, signed 64-bit integer, double, UTF-8
text, unibyte bytes, symbol name, and object handle. Symbols are not strings;
unibyte data is not UTF-8 text. Initially return unsupported/compound/live
objects as handles. Reject out-of-range integers instead of truncating.

Each request carries its session and correlation ID. Each handle carries
an opaque ID scoped to that session; an optional kind is informational,
not trusted type validation. Never serialize an address or =emacs_value=.
Define limits for message sizes, arguments, handles, queued requests, and
session inactivity. gRPC channels alone do not define session lifetime.

Define transport failures separately from Emacs signals/throws. Preserve
error symbol/tag and representable data, with a readable fallback. Call
=non_local_exit_check= after potentially exiting API operations; extract
and clear an exit before further normal Emacs API calls. Catch C++ exceptions
at C callback boundaries.

** TODO 6. Optional follow-up: remote callbacks

=make_function= accepts a local C callback, not an RPC payload. A later
=RegisterCallback= operation could create a local trampoline holding a
remote callback ID. This requires bidirectional messaging and defined
callback ownership, disconnect behavior, errors, cancellation, and recursion.

Decide reentrancy before implementation: blocking Emacs while a remote
callback calls back into Emacs can deadlock. Do not present arbitrary
synchronous callbacks as part of the initial supported contract.

Other later work: Ruby/Rust clients, higher-level Buffer/Window/Frame
wrappers, event subscriptions, and integration with bytecode artifacts.
