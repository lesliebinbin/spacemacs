* READY Ruby DSL to Emacs Lisp Transpiler

** Purpose

Provide a developer-friendly Ruby-like syntax/DSL for writing GNU Emacs extensions,
transpiling Ruby syntax into executable Emacs constructs without having to hand-author
nested Elisp parentheses.

This runbook is the single lifecycle, architecture decisions, and task record for the
feature.

** Architectural decisions

1. *Transpilation strategy: S-expressions first, Bytecode second*
   - *Phase 1 (Primary Target)*: Transpile Ruby AST to idiomatic Emacs Lisp S-expressions (=.el=)
     with lexical binding enabled (=;; -*- lexical-binding: t; -*-=).
     - Rationale: Human-readable output, full source-level debugging via =edebug=,
       clear error messages, and automatic access to Emacs's built-in byte compiler (=byte-opt.el=)
       and native compiler (=comp.el= / =gccjit=).
   - *Phase 2 (Advanced Target)*: Direct bytecode synthesis into compiled closures
     (=#[args-template byte-string constants-vector max-stack]=) and =.elc= files using
     =emacs-opcode-datasheet.md=.

2. *Parser selection: Ruby Prism*
   - Use Ruby core's official parser =Prism= (standard in Ruby 3.3+).
   - Inherit from =Prism::Visitor= to walk the syntax tree cleanly.

3. *Emacs Lisp Interop & Syntax Mapping*
   - Method definitions (=def foo(a, b)...end=) map to =(defun foo (a b) ...)=.
   - Dynamic/global variable access vs lexical stack variables: local variables map to =let*= scopes.
   - Ruby method calls (=buffer.name= or =point()=) map to Elisp function calls =(buffer-name)= or =(point)=.
   - Conditionals (=if=, =unless=, =case=) map to =(if ...)=, =(cond ...)=, or =(pcase ...)=.
   - Blocks/Lambdas map to lexical closures =(lambda (...) ...)=.

** Acceptance criteria

- [X] Transpiler parses a Ruby DSL source file and generates valid, readable S-expressions in =.el= format.
- [X] Emitted =.el= code passes =emacs -Q --batch -f batch-byte-compile= without warnings or errors.
- [X] Executed code produces identical behavior between Ruby source logic and Elisp evaluation.
- [X] Round-trip integration test runs via automated test harness (RSpec + Emacs batch runner).
